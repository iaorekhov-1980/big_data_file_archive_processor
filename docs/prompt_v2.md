## Промпт для агента: реализация ODS-модуля с абстракцией БД (PostgreSQL)

### Контекст
- Разрабатываем систему обработки домашнего файлового архива на Yandex Disk.
- Цель текущей задачи: реализовать **ODS-модуль** (сканирование источников, маркировка дубликатов, физическое удаление дубликатов, удаление пустых папок).
- Для гибкости и экономии средств на этапе разработки используем **локальный PostgreSQL** (в Docker) как БД. Позже будет добавлена реализация для YDB.
- **Код на Go**, структура проекта уже задана (см. ниже).
- Репозиторий GitHub: `big_data_file_archive_processor` (пустой). Нужно инициализировать его, создать структуру, написать код.

### Требования к архитектуре

1. **Абстракция базы данных**  
   - Определить интерфейс `Repository` в пакете `internal/repository`.  
   - Методы для работы с таблицами: `files`, `file_paths`, `source_processing`.  
   - Первая реализация – в `internal/repository/postgres`, используя драйвер `pgx`.  
   - Вторая (позже) – для YDB, сейчас не реализуем.  
   - Переключение через переменную окружения `DB_TYPE=postgres` (пока единственный вариант).  
   - Конфигурация подключения: `POSTGRES_DSN` (например, `postgres://postgres:password@localhost:5432/archive`).

2. **Модели данных** (`internal/models`)  
   - Соответствуют таблицам, описанным ранее.  
   - Использовать стандартные типы Go: `string`, `int64`, `time.Time`, `bool`.

3. **Миграции**  
   - Использовать инструмент `golang-migrate/migrate` (CLI).  
   - Миграции лежат в папке `migrations/`, содержат SQL для PostgreSQL.  
   - Скрипты создания таблиц (включая индексы) – в `000001_init.up.sql`.  
   - При старте приложения миграции **не** применяются автоматически; это будет сделано отдельно через команду `migrate`.

4. **ODS-функции** – три Cloud Functions, которые будут вызываться вручную (в дальнейшем через HTTP-триггеры).  
   - `scan_source` – сканирует папку источника, получает список файлов через API Yandex Disk, для каждого проверяет хеш, вставляет записи в `files` и `file_paths`. Обновляет `source_processing`.  
   - `cleanup_duplicates` – удаляет физически файлы, помеченные как `is_active=false` и `deleted_at IS NULL`.  
   - `cleanup_folders` – удаляет пустые папки рекурсивно.  
   - Все функции используют репозиторий через интерфейс, работают с Yandex Disk API через отдельный пакет `internal/disk`.

5. **Работа с Yandex Disk API**  
   - Пакет `internal/disk` – клиент для REST API.  
   - Реализовать методы:  
     - `ListFiles(sourceFolder, offset, limit)` – возвращает список файлов.  
     - `DeleteFile(path)` – удаляет файл.  
     - `GetFolderInfo(path)` – получает содержимое папки (для очистки).  
   - Использовать OAuth-токен (переменная окружения `YANDEX_DISK_TOKEN`).

6. **Конфигурация** – через переменные окружения:  
   - `DB_TYPE` (пока всегда `postgres`)  
   - `POSTGRES_DSN`  
   - `YANDEX_DISK_TOKEN`  
   - `LOG_LEVEL` (опционально)

7. **Структура проекта** (уже частично создана, но можно дополнить):
   ```

   ├── cmd/
   │   ├── scan_source/
   │   │   └── main.go
   │   ├── cleanup_duplicates/
   │   │   └── main.go
   │   └── cleanup_folders/
   │       └── main.go
   ├── internal/
   │   ├── models/
   │   │   └── models.go
   │   ├── repository/
   │   │   ├── interface.go
   │   │   ├── postgres/
   │   │   │   └── postgres.go
   │   │   └── factory.go
   │   ├── disk/
   │   │   └── disk.go
   │   └── config/
   │       └── config.go
   ├── migrations/
   │   ├── 000001_init.up.sql
   │   └── 000001_init.down.sql
   ├── terraform/ (пока пусто)
   ├── docs/ (документация)
   ├── go.mod

   ├── README.md
   └── .env.example
   ```

8. **Разработка поэтапно**:
   - Создать go.mod, .gitignore, README.
   - Реализовать модели и интерфейс репозитория.
   - Реализовать PostgreSQL-репозиторий (с подключением, методами).
   - Написать миграции.
   - Реализовать клиент Yandex Disk API.
   - Реализовать функцию `scan_source` (основная логика, тестирование вручную).
   - Реализовать `cleanup_duplicates` и `cleanup_folders`.
   - Зафиксировать всё в Git и запушить в GitHub.

### Дополнительные указания
- Не реализовывать YDB-репозиторий сейчас.
- При работе с Yandex Disk API учитывать лимиты (задержки между запросами).
- В `scan_source` для каждого файла при проверке хеша выполнять `SELECT` в транзакции? Можно без транзакций, но обеспечить идемпотентность через проверку существования пути перед вставкой.
- В `cleanup_duplicates` после удаления файла обновлять `deleted_at`.
- В `cleanup_folders` использовать рекурсивный обход папок, проверку через API, удаление.
